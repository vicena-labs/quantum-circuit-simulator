# Changelog

## 0.5.0rc3 (release candidate, not yet published) — research workflows and topological chips

- Add `chemistry`: PySCF molecules (named or by geometry) with active spaces, Jordan–Wigner, Bravyi–Kitaev and parity mappings, Z2 tapering, Hartree–Fock states and UCCSD; optional extra `chemistry`.
- Add `mitigation`: propagated noise absorption (`pna`), probabilistic error cancellation (`pec`, `pec_overhead`) and readout correction (`readout_correct`, `mitigated_counts`).
- Add `measurement`: qubit-wise and full-commutation grouping with diagonalising Cliffords, exact shot budgets with optimal allocation, and classical shadows.
- Add `dynamics` (Suzuki formulas of any even order, qDRIFT, Trotter commutator bounds, multi-product formulas); `trotter` and `evolution_step` take any even order.
- Add `resources`: T counts with rotation synthesis and surface-code estimates of distance, factories, physical qubits and runtime, from tetron chips' own error rates where given.
- Add `baselines` (brute force, simulated annealing, Goemans–Williamson) and `algorithms.qaoa(init="fixed-angle" | previous result | angles)`.
- Add Microsoft's Majorana 2 (`microsoft_majorana_2`) and Majorana tetron arrays (`tetron-array`) as a topological family: measurement-based gate costs, magic states and synthesized rotations in the compiler, parity-flip noise instead of T1/T2, every value cited or labelled an assumption, tetron CAD at the published dimensions.
- CAD writes 3D STL models; the README shows chip figures, exploded 3D views, a "Try it in Vicena" link and how to cite the package.

## 0.5.0rc2 (release candidate, not yet published) — converging deep truncated runs

- Add `--converge TOLERANCE` to `run` (with `--min-coefficient` and `--levels`) and `experiments.refine`: the truncation threshold tightens half a decade per level until two successive values agree within the tolerance, the term cap stops it or the time budget runs out, and `convergence` reports every level's threshold, values, bounds, peak terms and seconds. The finest finished level is kept when a later one overflows. `solve` uses the same path.
- Truncated results report `bound_informative`: false when the rigorous `error_bound` is no tighter than the trivial bound, as for IBM's 20-step kicked Ising circuit, where only convergence across levels supports the value.
- Raise the term cap's ceiling from 1,000,000 to 1,000,000,000 terms per cone (memory is the real limit, at about 0.5 KB per term at peak) and make 1,000,000 the default everywhere; the command line and JSON requests defaulted to 50,000.
- `rzz`, `rxx`, `ryy` and `rzx` become one native `RZZ` stage (in their basis frames) when a circuit is not compiled onto a chip, instead of seven stages through CZ, and `Circuit.gate("RZZ", ...)` takes a shared parameter on every backend. The same operator in fewer stages makes Pauli propagation of IBM's 20-step kicked Ising circuit about five times faster. Compiled circuits keep the chip's own gates; the compiler's ZZ crosstalk also uses one stage.
- Measured on IBM's 20-step kicked Ising circuit on `ibm_kyiv` (qubit 62, one core, Apple M-series): at θ = 0.2 the value converges to 0.9788 (change 0.0006) in under a second, and at θ = 0.4 to 0.8360 (successive levels 0.8347, 0.8361, 0.8360). At θ = 0.6 the levels still move by 0.05 at 5 million terms, and near π/2 the first level already needs over 10 million terms: those angles need far more terms than one laptop holds, as the converged published simulations also found, and the ladder reports them as unconverged.
- An overflow while truncating now says `truncated cone` rather than `exact cone`, and the hints name `--max-terms` and `--converge` explicitly.
- `run --threads` defaults to every core the process may use.
- The agent guide gains Python examples for compiling onto a real chip, exact noisy expectations, sampling and the convergence ladder.

## 0.5.0rc1 (release candidate, not yet published) — algorithm development, states and sampling, output contracts

- Bundle real chips: 65 IBM chips from the calibration snapshots in qiskit-ibm-runtime and Google's Rainbow, Weber and Willow Pink from cirq-google (both Apache-2.0), each with per-qubit T1, T2, readout and gate errors, per-coupler errors, gate durations, coordinates and, for IBM, qubit frequencies and anharmonicities. `devices.get("ibm_fez")`; `devices` lists them with snapshot dates. `tools/import_external.py` regenerates the data.
- The compiler's default gate model is now `thermal`: each gate relaxes its qubits for its duration and adds depolarizing noise for the rest of its measured error, applied when the source gate ends, after its decomposition's frame changes. On IBM snapshots this agrees with Qiskit Aer's noise model to within 0.01. `gate_model="depolarizing"` keeps the earlier model.
- Bundle a benchmark library: MQT Bench (MIT) and Supermarq (Apache-2.0) circuits at sizes up to 127 qubits, in OpenQASM 2 with this package's gates; `circuits.library()`, `circuits.load()`, the `circuits` command, and library names in sweeps. Add the `kicked-ising` family, IBM's 127-qubit utility experiment.
- Add `cad`: any chip as a GDSII, DXF or SVG placement layout (transmon crosses, couplers, readout pads or sites, in micrometres), written without dependencies, and the `cad` command.
- Add `annealing`: Ising and QUBO problems (from Hamiltonians, dicts or JSON), embedding with minorminer on new `dwave-advantage` (Pegasus P16) and `dwave-advantage2` (Zephyr Z12) devices or Chimera, Pegasus and Zephyr, rescaling to the chip's ranges, optional control errors, and simulated quantum annealing, simulated annealing, tabu or exact sampling; and the `anneal` command. The `dwave` extra now installs the Ocean packages it needs.
- Rename the package from Pauli Cones to Quantum Circuit Simulator (`pip install quantum-circuit-simulator`, `import quantum_circuit_simulator`, command `quantum-circuit-simulator`, repository `vicena-labs/quantum-circuit-simulator`). "Pauli cones" now names its main solver method. Result schemas are `quantum-circuit-simulator-<kind>/1`; device files written as `pauli-cones-device/1` still load.

- Accept up to 4,096 shared parameters (was 16). A parameterised gate's angle is `theta + scale * shift`, so one parameter can drive many gates with different weights, as QAOA's `gamma * w_ij` and a Trotter step's `2 h dt` need; Qiskit angles `k*p + b` stay shared. The native kernel computes gradients 16 parameters per pass over the same bound matrices; the graph backend computes all of them in one reverse pass, with its kernel's gradient width now dynamic. `Circuit.prepare` raises its default graph budget to 2,000,000 nodes and 10,000,000 edges, enough for ansatze with hundreds of parameters: on a 12-qubit, 120-parameter ansatz the graph returns the value and gradient in 5 ms, against 0.85 s for native passes.
- Add `Circuit.unitary` for any fixed one- or two-qubit unitary, and exact decompositions of `crx`, `cry`, `crz`, `ch`, `ccx` and `cswap` to the OpenQASM 2 reader. Observables take up to 65,536 terms (was 1,024).
- Add `pauli_cones.hamiltonians`: transverse-field Ising, Heisenberg/XXZ, Max-Cut and Fermi-Hubbard (Jordan–Wigner) models on chains, grids and random regular graphs; loaders for JSON, Pauli-sum strings, Qiskit `SparsePauliOp` and OpenFermion `QubitOperator`; qubit-wise commuting groups; exact ground energies (dense to 12 qubits, Lanczos to 22); and `trotter` (first or second order, time as a parameter) and `qaoa` (X or XY mixer) circuit builders. Circuits built in Python are `interop.Program`s with linear `Angle`s, accepted wherever OpenQASM or Qiskit circuits are.
- Add `pauli_cones.statevector`: amplitudes of noise-free circuits up to 28 qubits with adjoint gradients, density matrices up to 12 qubits, and sampling with noise and readout error, exact from the density matrix or one batched quantum trajectory per shot. Add `pauli_cones.stabilizer`, which samples Clifford circuits of any size through Stim (optional extra `stim`); T1/T2 relaxation is Pauli-twirled there and reported as approximate. `sample_compiled` simulates only the qubits a compiled circuit uses.
- `experiments.solve` gains gradients, the graph backend first when there are more than 16 parameters, the state vector (noise-free, up to 24 qubits) and density matrix (noisy, up to 10 qubits) before local dense cones and truncation, and `cross_check=True`, which compares a second, independent method.
- Add `pauli_cones.algorithms`: `Objective` (one reused plan, the faster of Pauli propagation and the state vector timed once), `minimize` with Adam, gradient descent, SPSA and L-BFGS and a full per-iteration trace, `hardware_efficient` ansatze, `vqe` with the exact ground energy as reference, `qaoa` with the approximation ratio and best sampled bitstring, `zne` (linear, quadratic, Richardson or exponential fits with a leave-one-out uncertainty and the ideal value for comparison) and `shot_noise` (exact group variances from Pauli expectations, optimal shot allocation).
- Output contracts: every command's result carries `schema` (`pauli-cones-<kind>/1`) and `provenance` (versions, platform, request SHA-256, seed, UTC time). Chips carry qubit coordinates for drawing them, kept through design operations, with a deterministic force-directed layout for custom chips. The compile report adds a `noise_budget` per qubit and per coupler with totals and an estimated fidelity, and `compile --schedule` lists every gate's physical qubits, start time and duration. `--progress` streams JSON-line progress events; `sweep --checkpoint FILE` resumes completed points and refuses a checkpoint from another request.
- New commands: `hamiltonian`, `optimize`, `sample`, `statevector`, `zne` and `shot-noise`. Devices are given as `name:k=v` everywhere. New optional extras `stim`, `algorithms` (SciPy) and `all`.
- `design.remove_qubits` now renumbers per-qubit noise with the qubits, and modular chips copy each module's per-qubit noise.

## 0.4.0rc4 (release candidate, not yet published) — faster native solver and graph, truncated mode, interop and agent-first CLI

- Add an optional truncated mode, `prepare(..., truncation=Truncation(min_coefficient, max_weight))`, on the `native`, `graph` and `auto` backends. It discards terms whose coefficients fall below a fraction of the observable's l1 norm, or that act on more than `max_weight` open wires. Every evaluation returns a rigorous `error_bound` and `gradient_error_bound`; exact plans return `None`. Other backends refuse truncation.
- Rewrite the native term store as a flat open-addressing table that a stage updates in place. Terms with identity on the stage's wires are not touched, terms the stage maps to themselves are rescaled in place, and only moved or branching terms are rehashed. Keys use one to four 64-bit words, chosen from each group's wire count.
- Propagate observables jointly when their combined backward cone fits the key width the widest single cone needs. The circuit is linear in the observable, so the result is unchanged while shared Pauli terms merge. A group that exceeds the term cap is split back into single cones, so no request that succeeded before now fails.
- Evaluate all cone groups in one native call, `run_pauli_batch`, with an optional `threads` count. Results are summed in group order and do not depend on the thread count. Wide `native` registers now use this path with one shared bound copy of the circuit instead of one prepared plan per cone.
- Read circuits from OpenQASM 2 (built in), OpenQASM 3 and Qiskit (`pauli_cones.interop`), with exact decompositions into the native gates. Qiskit Parameters entering angles as `p + b` or `-p + b` become shared parameters; others are bound per evaluation. Observables can be written as `"0.5*Z0*Z1 - X3"`, Qiskit labels, `SparsePauliOp` or JSON terms. `pauli_cones.interop.expectation` evaluates one in one call.
- Add `pauli_cones.estimator.Estimator`, a Qiskit Estimator V2 primitive that reuses one plan per observable across a parameter sweep and reports truncation error bounds.
- Add `pauli_cones.devices`: a JSON chip description (connectivity, native gates, gate infidelities, readout errors, coherence times, gate durations) and a catalogue of heavy-hex (including the 127-qubit Eagle-style layout), square-grid, line, all-to-all trapped-ion, neutral-atom and D-Wave-style Chimera, Pegasus and Zephyr chips. A device supplies the noise model for `expectation`, the Estimator and `--device` on the command line, converting gate infidelities to depolarizing probabilities with the same average fidelity, and reports two-qubit operations on uncoupled qubits. New `devices` and `device` commands.
- The greedy layout first searches for an exact placement with every interacting pair on a coupler (a backtracking subgraph match with degree pruning and a step budget), so chains, rings and lattices that fit need no SWAPs. Otherwise it keeps the best of eight well-spread greedy starts by routed SWAP count. The compile report names the method.
- Devices gain per-qubit noise (one-qubit error, readout, T1 and T2 overriding the chip's) and crosstalk: a depolarizing spectator error on started neighbours of each two-qubit gate, and an always-on ZZ rate giving every coupled pair of active qubits a conditional phase 2πζt for as long as both are active, idle or not. A coupler's own two-qubit gate replaces its ZZ during the gate. Phases are applied before the next X- or Y-type gate on either qubit, since diagonal gates commute with them. `experiments.solve` caps its exact attempt at 250,000 terms, so circuits whose exact expansion explodes (as coherent ZZ often makes them) move on to truncation quickly. The compiler applies both. `design.vary_qubits` spreads qubit values log-normally, `design.with_crosstalk` sets crosstalk, and `design.expand` and `design.series` grow chips with the same architecture: catalogue layouts regenerated larger, modular chips with more modules, other chips tiled. Sweeps grow a chip per size with `fit:` devices. New `design` options: `--qubit-spread`, `--seed`, `--spectator-error`, `--zz-hz` and `--expand-to`.
- Add `pauli_cones.design`: chips from coupler lists; added and removed couplers; removed qubits with renumbering; modular chips tiled from a module with line, ring or all-to-all links; gate errors from T1, T2 and gate durations (the exact coherence limit plus a control error); and `compare()`, which ranks chips on a benchmark family. Devices gain per-coupler errors, which the compiler applies gate by gate. New `design` and `compare` commands.
- Add `pauli_cones.experiments` with `solve()`, which tries exact native propagation, then exact dense for small cones, then truncation at two tolerances with a convergence check, and reports the method and whether the result is exact; and `sweep()`, which compiles and solves a circuit over chips, noise scales and sizes, returning rows with the ideal value, deviation, method and routing cost as JSON, CSV or Markdown. Add `pauli_cones.circuits` with GHZ, hardware-efficient, QAOA ring and Trotterized Ising families, and the `sweep` command.
- Add `pauli_cones.compiler`: compile a circuit onto a device with greedy or given layout, greedy shortest-path or Qiskit SABRE routing, as-soon-as-possible scheduling with the device's gate durations, gate errors, T1/T2 relaxation of idle qubits and readout error, moving observables to the final layout. New `compile` command and `--compile`, `--router`, `--layout`, `--noise-scale` and `--no-idle-noise` options.
- Apply readout error to measured Paulis of any axis (X and Y via the usual basis rotation), so device noise works with every observable.
- Make the command line agent-first. `run` and the new `plan` dry run accept OpenQASM files with `--observable` and a uniform noise model. New `capabilities`, `schema` and `guide` commands describe the tool as JSON and Markdown. Every error carries a `hint`. The JSON request accepts an OpenQASM form.
- When several joint cone groups exceed the term cap, split them all at once and retry once, instead of retrying the whole batch once per group; the batch and graph compiler report every group's status.
- Compile and evaluate the `graph` backend in C++. Observables are grouped into cones as for the native solver; each group's propagation is stored as flat edge arrays, terms a stage leaves unchanged get no edge, and an evaluation is one pass over the edges with one reverse pass for gradients. Graph plans take `threads`, support registers wider than 256 wires (`wide-graph`) and fall back to `wide-native` over budget. `stats` adds `cone_groups`; `nodes` and `edges` count the smaller graph.
- Truncate graphs too. A truncated graph chooses its discarded terms at the angles bound during preparation, keeps each discarded term as a node no edge reads, and computes the error bound from those terms' coefficients at every evaluation's own angles, so the bound holds at any binding. Truncated gradients use forward tangents, which the gradient bound needs. `numerics['truncation']['discarded_terms_chosen']` says which policy applies. When the value bound exceeds `Truncation.reprepare_factor` (default 2) times its value where the graph was compiled, the graph compiles again at the current angles; a recompilation over budget keeps the current graph and stops retrying. Diagnostics report `graph_reprepared` and `reprepare_failed`.
- Rebind rotation angles with vectorised NumPy writes into the native stage array instead of a Python loop over stages.
- The original C symbols and structure layouts are unchanged.
- Export the C entry points explicitly, so the extension loads on Windows, where unmarked functions are not exported.
- Make the sparse coefficient cutoff relative to the observable's l1 norm in the native kernel and Python reference. Observables with weights of 1e-16 or less previously returned exactly 0 on `native` and `python` while `graph` and `dense` returned the correct value. `numerics` reports `coefficient_cutoff_relative_to`.
- Enforce `max_cone_qubits` on registers of 256 wires or fewer; it was previously read only by the wide-register planner.

## 0.3.0a1 — scalable logical registers and backend extension

- Support 1–16,384 logical qubits through exact backward-causal-cone remapping to the existing <=256-wire native numerical engine; refuse wider active cones.
- Share the reverse graph pass for all requested observables, group identical local stage signatures and contract idle product-state wires analytically.
- Add explicit trusted external backend registration (`ext-*`) including full-width access, so non-Pauli engines can be developed independently.
- Add 4,096/16,384-qubit runnable demos, regression tests, and documented limits. Existing native numerical kernel and historical speed claims remain unchanged.


## 0.2.0a2 — developer toolkit

Add a validated, undirected coupling graph helper and runnable architecture playground for line/grid/custom graphs. Add a small educational MaxCut QAOA circuit with verified analytic gradients, a variational-energy gradient-descent example, an accuracy-checked within-package backend comparison, and a capability inventory that explicitly distinguishes integrated speedups from retained experimental runners and separate general-purpose quantum solvers. No numerical C++ or Python backend is changed.

## 0.2.0a1 — architecture cleanup and reproducible comparisons

Contract known product inputs as soon as backward propagation reaches each wire's first operation, including idle readout before expansion. Specialize occupied local PTM rows, preserve derivative-only transitions, and construct rotation transfers analytically. Add scalar native execution, public value-only methods and CLI controls; canonicalize duplicate observables.

Add bounded reusable arithmetic graphs with reverse differentiation, local density matrices with channel-adjoint gradients, and an explicit sparse-to-dense capacity fallback. Report the selected representation, fallback reason and numerical policy. Preserve existing native C ABI layouts and use one maintained kernel for experimental runners.

Add independent noisy numerical tests, matched external CPU comparisons, fresh-angle revision comparisons, source hashes and raw failure records. Apply Apache-2.0 licensing for source distribution. No compiled release or blanket simulator-speed claim is made.

## 0.1.0a1 — source-only alpha candidate

Extract a standalone package from the numerical research prototype. Retain the original sparse Pauli recurrence and float64 filtering. Add a validated Circuit/Prepared API, explicit native/reference backends, versioned JSON CLI with worker deadlines, self-contained examples and installed-wheel tests. Build the native extension at installation time rather than import time.

Calibrated device fixtures and private application content are excluded. The initial publication and licensing decisions remain pending. This is not a PyPI release or a production readiness claim.
